# Team Builder — Design

**Goal:** A new page on the site where the user builds their own XI — pick any
formation, click a circle on a drawn pitch to fill each position from a searchable
player list, see the player's photo in the circle — and gets coach suggestions for
the team they built, using the same similarity engine as the team pages.

Status: design agreed 2026-07-14; not yet implemented.

Settled decisions (Andrew, 2026-07-14):

| Decision | Choice |
|---|---|
| Player pool | **All big-5, any season** — every archetype-qualifying player-season 2015/16–2024/25 (~17,200), plus goalkeepers from the same team-seasons. Cross-era teams allowed (2017/18 De Bruyne next to 2015/16 Vardy). |
| Coach suggestion | **Similarity grid** — the team-page engine: archetype-share cosine similarity against coach profiles, 85/15 similarity/quality blend, plausibility chips. Descriptive labeling carries over unchanged. |
| Player photos | **New TM scrape** — resumable headshot scraper following the coach-image pattern; initials-badge fallback so the page never breaks. |
| Position eligibility | **Recommender matrix** — `cr_archetype_slot_matrix` (+ TM-position fallback) decides which players a slot offers. |

---

## 1. Why this is mostly assembly, not invention

Every hard piece already exists in `coach_recommender.R` and the exporter:

- **Formations:** `cr_formation_slots` hand-maps all 22 formation strings observed in
  36,022 big-5 team-matches to slot counts (CB/FB/DM/CM/AM/W/ST + implicit GK).
- **Eligibility:** `cr_archetype_slot_matrix` (11 archetypes × 7 slots, soft
  penalties) and `cr_tm_position_slot()` (fallback at a 0.9 discount) were validated
  mechanically (fit → minutes t = 26.9 at 316 coach arrivals).
- **Suggestion engine:** the similarity layer (`cr_` composition profiles: residual-
  softmax-tilted stint archetype shares, τ = 0.2; self-similarity gate passed at the
  82nd percentile) and the exporter's 85/15 z-score blend (`se_suggestions()`).
- **Frontend patterns:** filter chips, badge rendering, similarity cards, search with
  keyboard navigation, image fallbacks — all in `site/js/components.js` + `team.js`.

What is genuinely new: a player-level data export, a player photo scrape, pitch
coordinates for the 22 formations, and the builder page itself. Plus one engine
change: similarity is currently computed *in R per team*; the builder needs it
computed *in the browser against an arbitrary XI*, so the export ships coach profile
vectors instead of precomputed similarity scores.

## 2. Player pool and data export

### 2.1 Pool definition

One selectable unit = a **player-season**:

- **Outfielders:** every archetype-qualifying player-season (≥600 league minutes,
  non-GK) in `archetypes.rds` — ~17,219 rows. Each carries its own-season archetype
  (the style actually observed that season; the M6 lagging guard is an endogeneity
  device for inference and is irrelevant for a fantasy builder).
- **Goalkeepers:** GK rows from `players.rds` for the same big-5 team-seasons,
  ≥600 minutes (GKs have no archetype; they are eligible only for the GK slot).

Joined via the season crosswalks to TM `player_id` for value, age, TM position, and
the photo key. A player-season with no TM match (the ~0.7% youth-player residue) is
dropped from the pool.

### 2.2 Export shape (`site/data/builder/`)

- `players.json` — grouped by TM player id to avoid repeating names/photos:
  `{ id, name, photo, seasons: [{ y, league, club, club_id, value, pos, arch }] }`.
  ~17k season rows across ~8–10k players; estimated 2–4 MB raw. If it exceeds
  ~5 MB, split into `players_D/M/F/G.json` loaded lazily per slot type (slot →
  position-group mapping makes this natural). Length-1 arrays wrapped in `I()` as
  everywhere else.
- `coaches.json` — the suggestion pool: coaches with ≥4 big-5 stints and positive
  career residual (same bar as team pages, ~150). Per coach: numeric id, name, grade
  + cut label, quality BLUP (for the blend), the **11-dim similarity profile
  vector**, career facts needed for badges (leagues, countries, big-5 games, club
  level percentile, last season, nationality), stint count, career residual.
- `meta.json` — the 22 formations with **slot lists incl. pitch coordinates**
  (`{ type: "FB", side: "R", x, y }`, hand-mapped in R next to `cr_formation_slots`
  so both stay in sync), the archetype → slot eligibility matrix, the TM-position
  fallback table, archetype labels, badge thresholds (level band, active-since) —
  the frontend stays a dumb renderer, consistent with house style.

All generated by a new `se_export_builder()` inside `export_site_data()` (wipe-and-
rebuild like the rest of `site/data/`).

### 2.3 Player photos (new scrape)

- `xx_raw_player_image_url(player_id)` + `xx_data_populate_player_images()` in
  `source_data.r`, cloning the coach-image pattern exactly: 2s sleep, lookup cache
  `data/cache/player_images.rds`, files at `data/images/players/<tm_numeric_id>.jpg`,
  confirmed-missing recorded as NA, transient failures retried, resumable,
  per-player saves. Player profile pages use the same
  `img.data-header__profile-image` header element as trainer pages.
- **Priority order: pool players by career minutes** (like the nationality scrape's
  ranked-coaches-first ordering) so an interrupted run covers the players people
  will actually search for. ~8–10k unique players ≈ 5–6 h total; can run across
  sessions.
- Export copies only pool players' photos to `site/assets/players/`. Fallback chain
  in the UI: photo → initials badge (existing `components.js` pattern). **Repo-size
  note:** ~10k photos ≈ 100–120 MB; if that is too heavy to commit, gitignore
  `site/assets/players/` + `data/images/players/` and regenerate on demand (the
  July-10 log already flags this option for `site/data/`).

## 3. The builder UI (`site/builder.html`, `site/js/builder.js`)

### 3.1 Pitch and formation

- Vertical half-pitch-style SVG (goal at the bottom, attack up), drawn with the
  existing hand-rolled chart conventions and theme variables; renders in both
  themes.
- Formation `<select>` listing all 22 strings, grouped by family (back-4 / back-3,
  striker count) for scannability. Default `4-3-3`.
- Eleven circles at the coordinates from `meta.json`. Changing formation re-lays-out
  the circles; players already picked are **kept if the new formation has a slot
  they're eligible for** (greedy re-assignment, highest eligibility first), others
  drop to a small "bench" strip below the pitch to be re-placed or removed — no
  silent deletion of the user's picks.

### 3.2 Slot interaction

- Click a circle → a picker panel (same overlay pattern as the team-page carousel):
  search box + list of eligible player-seasons.
- **Eligibility:** archetype row of `cr_archetype_slot_matrix` (TM fallback where
  the season somehow lacks an archetype); a player-season appears for a slot when
  its factor ≥ 0.25. Rendered in three groups: **Natural** (1.0), **Capable**
  (≥ 0.5), **Stretch** (≥ 0.25) — this is exactly the "RB can play RM, attackers
  play any attacking slot" allowance, but grounded in the validated matrix instead
  of ad-hoc rules. GK slot lists goalkeepers only.
- Sort within group: market value descending. For sided slots (LB/RB, LW/RW), TM
  position side (Left-/Right-) sorts matching-side players first; it never filters.
- List rows: photo/initials, name, season (e.g. "2019/20"), club + crest, value,
  archetype label chip. Search matches name substrings (reuse the search component).
- Picking fills the circle with the photo (initials fallback), name + season label
  beneath; a small × clears the slot. **Rule: the same TM player may appear only
  once per team** — other seasons of an already-picked player are disabled in the
  picker with a "already in your XI (2017/18)" note.

### 3.3 Team readout

Below the pitch, live as slots fill: total XI value; an archetype-mix bar (the
11-share vector the suggestion engine will consume); count of filled slots. A note
that values are nominal per season — cross-era totals mix inflation eras (writeup
limitation language).

### 3.4 Shareable builds

The whole build serializes into the URL hash (`#f=4-3-3&s=<slot:player-season ids>`),
like existing pages' id params — bookmarkable and shareable with zero backend, and
it makes QA reproducible.

## 4. Coach suggestions for the built team

### 4.1 Computation (client-side, mirrors `se_suggestions()`)

Runs when all 11 slots are filled; recomputes on any change:

1. **Team composition vector:** equal-weight mean of the 10 outfielders' archetype
   one-hot vectors (each starter is assumed to play the same minutes — the builder
   analog of minutes-weighted shares; GK contributes nothing, matching how stint
   shares are computed over outfield minutes).
2. **Similarity:** cosine similarity against each pool coach's profile vector.
3. **Ordering:** z-score similarity and quality BLUP within the pool, rank by
   0.85 × sim + 0.15 × quality — the exact blend the team pages use (keep the two
   implementations numerically consistent; a unit check compares JS output against
   an R-exported fixture for one reference XI).
4. Render the **same similarity card grid** as team pages: photo, name, grade chip
   with cut label, rank number from the full default ordering (stable under
   filters), similarity meter, % match, career residual, stints, badges. 9 cards
   shown; filters backfill from the full pool.

### 4.2 Plausibility chips on a team with no identity

A custom team has no league or country, so two chips need a context: an optional
**"League context"** selector (the 5 big-5 leagues) next to the suggestions header.

- Unset (default): *this-league* / *this-country* / *domestic* chips are disabled
  with a tooltip ("pick a league context"); *big-5 proven*, *recently active*, and
  *similar level* remain available.
- *Similar level* uses the built XI's total value percentile against that season-
  latest league's clubs when a context is set, and against all big-5 clubs when not
  (band threshold shipped in `meta.json`, currently ±10 points).

### 4.3 Labeling (binding)

The similarity layer is descriptive. The card carries the same footnote family as
team pages: coaches who thrived with squads *shaped like* this one; the ranking
tilt is disclosed; the validated quality ranking lives on the leaderboard, linked.
No fit/deployment numbers appear anywhere on this page (they are exploratory and
team-page-only today; nothing here changes that verdict).

## 5. What this feature deliberately does not do

1. **No predicted points for the fantasy XI.** The M3 model is calibrated on real
   squads' minutes-weighted values within a league-season; a cross-era all-star XI
   is far outside its support, and any PPG number would be theater.
2. **No per-coach fit scores** (recommender payoff verdict is binding).
3. **No bench/rotation modeling** — the XI is the team.
4. **No formation-fit term in the suggestion** — the similarity engine sees archetype
   shares only. (A coach's formation profile vs the chosen formation is a candidate
   *badge* — "plays 3-4-2-1: 62% of recent matches" — noted as a future nicety, not
   in scope.)

## 6. Implementation plan

New code: `se_export_builder()` in `src/site_export.R`; player-image scraper in
`src/source_data.r`; `site/builder.html`, `site/js/builder.js`; CSS additions.
Header nav gains a "Team builder" link on all pages. Phases, each gated:

| Phase | Deliverable | Gate |
|---|---|---|
| 0 | Pool sizing: exact unique-player count, JSON size, GK counts; freeze split-file decision and photo-commit decision | numbers recorded |
| 1 | Player photo scraper + priority run started (runs in background across sessions) | resumability verified by kill/restart; lookup semantics match coach-image scraper |
| 2 | `se_export_builder()`: players/coaches/meta JSON + slot coordinates for all 22 formations | link sweep: every id/photo/crest resolves; every formation's slots sum to 10 + GK; JS/R similarity fixture check passes |
| 3 | Pitch + formation UI: layout, slot circles, formation switch with pick preservation | all 22 formations render sanely at desktop + 375px, both themes |
| 4 | Picker panel: eligibility groups, search, dedupe rule, photo fill | spot checks: Van Dijk not offered at ST; Alexander-Arnold offered at RM as Stretch/Capable; GK slot GKs only |
| 5 | Suggestions: composition, cosine, blend, cards, chips, league-context selector | City-2024/25-replica XI reproduces the team page's grid order; chips verified live |
| 6 | URL-hash persistence + QA (chromote screenshots, link sweep) + docs (CLAUDE.md website section, Milestones, session log) | round-trip: paste URL → identical team |

Rough order of effort: the scrape is wall-clock-long but hands-off; phases 2–5 are
the real build, comparable to one team-page-scale feature.

## 7. Known limitations (to state on the page / in the writeup)

1. **Pool = big-5, 2015/16–2024/25, ≥600 minutes.** No Championship players, no
   pre-2015 legends, no sub-600-minute breakout seasons.
2. **Cross-era market values are nominal** — a 2015 valuation and a 2024 valuation
   are different currencies; the total-value readout says so.
3. **Suggestions are descriptive similarity**, inheriting all the team-page caveats;
   the archetype-share representation ignores formation, chemistry, and era.
4. **Equal-minutes composition** is an approximation of the minutes-weighted shares
   the coach profiles were built from.
5. **Eligibility is archetype-level**, blind to footedness and individual
   versatility beyond what the archetype encodes; sided sorting is cosmetic.
6. **Photo coverage** will be partial until the scrape completes (initials fallback
   covers the gap, as with coach images).
